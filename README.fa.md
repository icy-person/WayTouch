# WayTouch

**نگاشت ورودی ماوس و صفحه‌کلید لینوکس به کنترل‌های لمسی و ماوس اندروید در Waydroid**

[English](README.md) · [راهنمای مشارکت](CONTRIBUTING.md)

WayTouch امکان کنترل برنامه‌ها و بازی‌های اندروید در Waydroid را با ماوس و صفحه‌کلید کامپیوتر لینوکسی فراهم می‌کند. برنامهٔ میزبان با Rust رویدادهای ورودی لینوکس را دریافت و به فرمان‌های لمسی یا رویدادهای ماوس اندروید تبدیل می‌کند. تنظیمات از طریق رابط دسکتاپ انجام می‌شود و ویرایشگر اندروید برای چیدن کنترل‌ها روی صفحه به کار می‌رود.

مخزن فعلی برای Linux x86_64 و Waydroid آماده شده است. رفتار ورودی تزریق‌شده در بازی‌ها یکسان نیست؛ بنابراین ممکن است لازم باشد چیدمان و کلیدها را برای هر بازی جداگانه تنظیم کنید.

## قابلیت‌ها

- تبدیل کلیدهای صفحه‌کلید به دکمه‌های لمسی اندروید.
- جوی‌استیک مجازی برای حرکت با کلیدهای دلخواه.
- ارسال حرکت ماوس، دکمه‌ها و اسکرول به‌صورت ورودی بومی ماوس اندروید.
- دو حالت کنترل دوربین: **Relative Mouse** و **Touch Drag**.
- تنظیم حساسیت افقی و عمودی، وارونگی محور Y، نرمی حرکت، Deadzone و سرعت کرسر.
- پشتیبانی از حداکثر ۱۰ اشاره‌گر لمسی هم‌زمان.
- ویرایشگر اندروید برای جابه‌جایی کنترل‌ها و تغییر کلیدهای متصل به آن‌ها.

## نحوهٔ کار

```text
ماوس و صفحه‌کلید
       |
       v
برنامهٔ میزبان Rust در لینوکس
       |
       | ارتباط از طریق ADB
       v
سرویس WayTouch در اندروید
       |
       v
برنامه یا بازی اندرویدی
```

بخش Rust ورودی فیزیکی را می‌خواند و نگاشت‌ها را اجرا می‌کند. سرویس اندروید رویدادهای لمس و ماوس را به سیستم ورودی Android می‌فرستد. رابط دسکتاپ و ویرایشگر اندروید برای تنظیم پروفایل و محل کنترل‌ها استفاده می‌شوند.

## بخش‌های پروژه

| مسیر | کاربرد |
|---|---|
| `rust-host/` | دریافت ورودی لینوکس، نگاشت کلیدها، کنترل ماوس، شناسایی دستگاه‌ها و CLI |
| `android-server/` | سرویس Kotlin که در محیط اندروید Waydroid اجرا می‌شود |
| `android-editor/` | برنامهٔ اندروید، اعلان WayTouch و ویرایشگر چیدمان کنترل‌ها |
| `gui/` | رابط دسکتاپ با PySide6 و Qt Quick |
| `profiles/` | مسیر دستگاه‌ها، نگاشت کلیدها و تنظیمات چیدمان |
| `scripts/` | اسکریپت‌های نصب، ساخت، راه‌اندازی و آزمون |
| `assets/` | آیکون‌ها و فایل‌های گرافیکی برنامه |
| `.github/` | گردش‌کار CI و قالب Pull Request |

## کلیدهای پیش‌فرض

| کلید یا ورودی | عملکرد |
|---|---|
| `W`، `A`، `S`، `D` | حرکت جوی‌استیک مجازی |
| `F1` | گرفتن یا آزادکردن ماوس فیزیکی |
| `F2` | فعال یا غیرفعال‌کردن نگاشت دکمه‌های ماوس به لمس |
| `F3` | روشن یا خاموش‌کردن Aim هنگام فعال‌بودن گرفتن ماوس |
| `Ctrl` + `Alt` + `Esc` | توقف کنترلر و آزادکردن دستگاه‌های ورودی |

دکمه‌های دیگر و محل قرارگیری آن‌ها در پروفایل تعریف می‌شوند و از طریق رابط دسکتاپ یا ویرایشگر اندروید قابل تغییرند.

## پیش‌نیازها

- Linux x86_64
- Rust `1.99.1`
- Kotlin compiler `2.4.21`
- JDK `21`
- Android SDK platform `37.0`
- Android Build Tools `36.0.0`
- D8/R8 `9.1.41`
- Python نسخهٔ `3.10` یا جدیدتر و PySide6 نسخهٔ `6.12.0`
- ابزارهای `git`، `make`، `curl`، `unzip`، `zip`، ابزارهای کامپایل C و `sdkmanager`

برای نصب و اجرای WayTouch به Waydroid و ADB نیاز دارید؛ اما ساخت محلی پروژه و آزمون‌های مستقل از دستگاه به اتصال اندروید احتیاج ندارند.

## آماده‌سازی محیط توسعه

در CachyOS یا Arch Linux بسته‌های پایه را نصب کنید:

```bash
sudo pacman -S --needed base-devel git curl unzip zip make \
  jdk21-openjdk python python-pip
```

Rust را با [rustup](https://rustup.rs/) نصب کنید. ابزارهای خط فرمان Android SDK را نیز نصب و مجوزهای SDK را تأیید کنید:

```bash
sdkmanager --licenses
```

مسیر Android SDK را مشخص و بسته‌های موردنیاز پروژه را نصب کنید:

```bash
export ANDROID_HOME="$HOME/android/SDK"
export ANDROID_SDK_ROOT="$ANDROID_HOME"

sdkmanager --install \
  'platforms;android-37.0' \
  'build-tools;36.0.0'
```

حالا از پوشهٔ اصلی مخزن اجرا کنید:

```bash
make setup
make doctor
```

`make setup` محیط مجازی Python را در `.venv/` می‌سازد، وابستگی‌های Python را نصب می‌کند و Kotlin compiler موردنیاز پروژه را آماده می‌کند. نسخهٔ Rust نیز در `rust-toolchain.toml` مشخص شده است.

## ساخت پروژه

برای ساخت برنامهٔ میزبان، سرویس اندروید و APK ویرایشگر و اجرای بررسی‌های خودکار، دستور زیر را اجرا کنید:

```bash
make build
```

دستورهای پرکاربرد:

| دستور | کاربرد |
|---|---|
| `make setup` | آماده‌سازی ابزارهای محلی Python و Kotlin |
| `make doctor` | بررسی پیش‌نیازها و نسخهٔ ابزارها |
| `make build` | ساخت بخش‌های پروژه و اجرای آزمون‌های خودکار |
| `make test` | اجرای بررسی‌های کامل بیلد |
| `make rust-test` | بررسی فرمت، تست‌ها و Clippy در Rust |
| `make fmt` | فرمت‌کردن کدهای Rust |
| `make fmt-check` | بررسی فرمت Rust بدون تغییر فایل‌ها |
| `make lint` | اجرای Clippy با خطا محسوب‌شدن هشدارها |
| `make android-editor` | ساخت APK ویرایشگر اندروید با امضای Debug |
| `make clean` | حذف خروجی‌های تولیدشدهٔ بیلد |

خروجی‌های اصلی در این مسیرها قرار می‌گیرند:

```text
rust-host/target/release/waytouch-host
android-server/build/waytouch-server.jar
android-server/build/dex/classes.dex
android-editor/build/waytouch-editor.apk
```

APK معمولی با کلید محلی Debug امضا می‌شود و برای توسعه و آزمایش است، نه انتشار عمومی.

## اجرا در Waydroid

ابتدا Waydroid را اجرا و ADB را متصل کنید:

```bash
waydroid status
waydroid adb connect
adb devices -l
```

پروژه را بسازید و ویرایشگر اندروید را نصب کنید:

```bash
make build
./scripts/install-android-editor.sh
```

سرویس اندروید را اجرا کنید:

```bash
./scripts/start-server.sh
```

رابط دسکتاپ را باز کنید:

```bash
./scripts/waytouch-gui
```

در بخش **Input devices** ماوس و صفحه‌کلید موردنظر را شناسایی و انتخاب کنید. پیش از راه‌اندازی کنترلر، دستگاه‌های انتخاب‌شده و پروفایل فعال را بررسی کنید. ویرایشگر اندروید از طریق اعلان WayTouch در دسترس است.

برای افزودن میان‌بر برنامه به منوی دسکتاپ:

```bash
./scripts/install-desktop.sh
```

## پروفایل و دستگاه‌های ورودی

فایل `profiles/default.json` اندازهٔ نمایشگر، مسیر ماوس و صفحه‌کلید، تنظیمات جوی‌استیک، حالت کنترل دوربین، کرسر و دکمه‌های عملیاتی را نگه می‌دارد.

مسیر دستگاه‌های ثبت‌شده در پروفایل نمونه ممکن است با سیستم شما تفاوت داشته باشد. قبل از اجرا آن‌ها را در رابط گرافیکی بررسی کنید یا از دستورهای زیر کمک بگیرید:

```bash
./rust-host/target/release/waytouch-host devices
./rust-host/target/release/waytouch-host discover
```

برای بررسی پروفایل و ثبت مسیر دستگاه‌های شناسایی‌شده:

```bash
./rust-host/target/release/waytouch-host profile-check profiles/default.json
./rust-host/target/release/waytouch-host discover --apply profiles/default.json
```

پس از اعمال مسیرها، پروفایل را دوباره بررسی کنید. WayTouch در صورت وجود از مسیرهای پایدار `/dev/input/by-id` و `/dev/input/by-path` استفاده می‌کند؛ مسیر دستگاه یک رایانه را بدون بررسی روی رایانهٔ دیگر کپی نکنید.

## گرفتن ورودی و نکات ایمنی

هنگامی که کنترلر فعال است، دستگاه‌های انتخاب‌شده از طریق Linux evdev به‌صورت انحصاری در اختیار WayTouch قرار می‌گیرند. در این حالت برنامه‌های دسکتاپ دیگر ورودی همان ماوس یا صفحه‌کلید را دریافت نمی‌کنند. برای توقف و آزادکردن دستگاه‌ها از `Ctrl` + `Alt` + `Esc` استفاده کنید.

ارتباط Android از طریق ADB و با یک توکن اختصاصی برای هر بار اجرا انجام می‌شود. توکن میزبان در مسیر `$XDG_STATE_HOME/waytouch/` یا در نبود آن در `$HOME/.local/state/waytouch/` ذخیره می‌شود. این فایل را در اختیار دیگران قرار ندهید و وارد Git نکنید.

## آزمون‌ها

`make build` آزمون‌های موجود Rust، Python، Qt/QML، کامپایل Android و بسته‌بندی APK را اجرا می‌کند. آزمون‌هایی که به Waydroid و دستگاه متصل نیاز دارند جداگانه اجرا می‌شوند:

```bash
python3 scripts/test-input-pipeline.py
python3 gui/test_backend_live.py
python3 scripts/test-touchdrag-stress.py
```

آزمون `gui/test_backend_live.py` هنگام اجرا دسترسی انحصاری به دستگاه‌های ورودی انتخاب‌شده می‌گیرد. پیش از اجرای آن برنامه‌هایی را که به ماوس یا صفحه‌کلید نیاز دارند ببندید.

موفقیت آزمون‌های ساخت به معنی سازگاری با تمام بازی‌های اندروید نیست. پذیرش رویدادهای لمس و ماوس را باید روی نسخهٔ Waydroid و بازی موردنظر بررسی کنید.

## مشارکت در توسعه

برای نصب ابزارهای توسعه، دستورهای ساخت و آزمون‌های دستگاه‌محور، [CONTRIBUTING.md](CONTRIBUTING.md) را بخوانید. تغییرات را به بخش مرتبط محدود کنید، برای تغییر رفتار آزمون اضافه کنید و فایل‌های خروجی، کلید امضا یا توکن IPC را وارد مخزن نکنید.

## محدودیت‌های فعلی

- Backend ورودی به evdev لینوکس وابسته است؛ ساخت و اجرای کنترلر میزبان در Windows و macOS پشتیبانی نمی‌شود.
- اسکریپت‌های نصب و راه‌اندازی برای Waydroid نوشته شده‌اند و محیط‌های دیگر اندروید جزو هدف فعلی پروژه نیستند.
- سازگاری با بازی‌ها به نحوهٔ دریافت رویدادهای لمسی و ماوس در هر بازی بستگی دارد.
- پروفایل پیش‌فرض نمونه است و محل کنترل‌ها و کلیدها باید با نمایشگر و بازی موردنظر تنظیم شوند.
- تا زمانی که کنترلر فعال است، دستگاه‌های ورودی انتخاب‌شده در اختیار برنامه‌های دیگر دسکتاپ نیستند.
